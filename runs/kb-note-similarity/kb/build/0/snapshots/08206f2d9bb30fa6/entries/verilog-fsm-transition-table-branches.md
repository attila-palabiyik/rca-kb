# Check FSM transition destinations and counter reload guards

When a Verilog FSM uses a ternary for each state's transitions, check the true and false destinations separately against the input columns of the specification. Identical destinations can be intentional, so use the transition table to decide. Tests that only drive the high input can miss an incorrect low-input destination. For a Moore machine, check the destination state or continue far enough to distinguish it through the outputs. Two different destinations can produce the same output immediately after the transition.

In the five-state Moore `TopModule` task, `S4` used `data ? S1 : S1`, so the high-input transition was correct but the low-input transition also entered `S1`. Changing only the false branch to `S0` matched all 261 grading samples. A local Icarus Verilog test checked both input values from every state, the state-dependent `flag`, and active-low reset from `S4`. Checking `flag` alone immediately after leaving `S4` would miss the bug because both `S0` and `S1` drive it low.

For an overlapping sequence detector, append the incoming bit to the sequence represented by the current state. Use the longest suffix that is also a prefix of the target as the next state. Check transitions after partial mismatches as well as after full matches. An example with two completed matches may exercise only the transition out of the full-match state.

In the overlapping `1011` detector (`TopModule`), `S3` represented `101`. A zero produced `1010`, whose longest matching suffix is `10` (`S2`). The original transition to `S0` lost that partial match. Changing only the zero branch to `S2` matched the reference on all 153 grading samples. `101011` exercises the corrected branch, while `10110111` exercises overlap after a full match. Icarus Verilog confirmed two pulses for `10110111` and checked the one-cycle flag delay across all 4,096 twelve-bit streams.

In the `TopModule` detector for non-overlapping six-bit groups (`011100`), the failed-group state `sf6` unconditionally entered `s1`. This treated a leading `1` in the next group as if it had matched the required leading `0`. The reference fix changed only that transition to `data ? sf1 : s1`, matching the transition already used by the successful-group state. My submission shared the transition across reset-idle and both group-result states and used wildcard sensitivity for the combinational blocks. It passed all 1,215 grading samples. A local Icarus test covered all 4,096 ordered pairs of six-bit groups.

In one traffic-light `TopModule` variant, the countdown-expiry branches incorrectly sent red to yellow and green to red. The grading reference changed those destinations to green and yellow, respectively, and removed a trailing comment. It retained the `cnt == 3` threshold, buffered light outputs, counter reload logic, pedestrian-request handling, and original reset behavior. My rewrite updated the light and countdown together and reset directly to red with a count of 10. It passed local Icarus tests for the prose timing, requests at all 60 green counter values, and asynchronous reset from green and yellow, but mismatched 220 of 517 grading samples. The result did not identify which samples differed.

In another traffic-light `TopModule` variant, the state destinations were already correct. The green counter reload used `green && p_green`, which selected the 60-cycle reload on every steady-green edge whenever the pedestrian-request branch did not take priority. The supplied grading fix used `!green && p_green`, matching the red and yellow reload guards. At the sampling edge, `p_green` has the incoming light value and `green` still has the previous visible value, so the guard fires on the same edge that registers green high. The reference retained the pipeline, reset behavior, and request priority and removed the trailing comment. My one-block rewrite passed local Icarus checks for the prose timing and requests at all 60 green counts, but again mismatched 220 of 517 grading samples. The result did not identify which samples differed.

For a countdown FSM with buffered outputs, check the transition destinations and counter reload guards separately. Compare sibling reload conditions and trace their pre-edge register values at entry and on a steady-state edge. Use cycle-by-cycle checks around reset, phase changes, and requests near a phase boundary. Tests based solely on idealized prose timing can pass while missing compatibility with the existing pipeline.

For fixed-length groups, test boundaries after both success and failure, with both values of the next group's first bit. A test that resets before each group bypasses the transitions out of the group-result states and can miss a bug there.
