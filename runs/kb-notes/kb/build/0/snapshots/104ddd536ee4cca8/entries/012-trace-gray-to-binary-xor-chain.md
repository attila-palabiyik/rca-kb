# Check Gray-code conversion and output timing

In the 4-bit Gray counter `TopModule`, the least significant binary bit XORed `gray_wire[0]` with `bin_out[3]`. The reference fix used `bin_out[1]`, the already-decoded bit immediately above it. The existing blocking assignments evaluate that chain from most significant to least significant bit within the clocked block.

The submitted fix computed the same chain with combinational wires and captured the complete decoded value with a nonblocking assignment. It matched all 421 grading samples. The one-line reference fix shows that the XOR operand was sufficient to repair the graded behavior. Icarus Verilog also verified the submitted fix across all 16 values, wraparound, and asynchronous reset during counting. No alternate repair failed.

In a separate `TopModule` task with the same 4-bit Gray counter structure, the decoder already used the correct XOR chain. The bug was in the encoder, which used `bin ^ (bin >> 2)`. The one-line reference fix changed the shift to `>> 1` and kept the existing registers and assignments. The submitted fix also changed the registered decoder to use nonblocking assignments with prefix XORs. It matched all 421 grading samples, and Icarus Verilog verified the full sequence, hold cycles, one-bit transitions, wraparound, and asynchronous reset. No alternate repair was simulated on this task.

For Gray-to-binary conversion, check that each decoded bit is the XOR of its Gray bit and the decoded bit immediately above it. Gray `0011` should decode to binary `0010` and exposes the skipped dependency. For binary-to-Gray conversion, each bit below the MSB is the XOR of two adjacent binary bits. Binary `0010` should encode to Gray `0011` and exposes a two-bit shift. For a feedback counter, check the expected output on every edge through wraparound so the test covers both the value sequence and the hold cycles.

In a third 4-bit Gray counter `TopModule` task, both conversions were already correct. The submitted fix changed the decoder to use nonblocking assignments with prefix XORs and kept `gray_out` combinational. An Icarus test passed with the first visible increment on the first rising edge after reset, followed by increments every other edge. Grading reported 202 mismatches out of 421 samples.

The reference fix registered `gray_out` on the rising edge with active-low asynchronous reset and preserved the decoder and increment stages. With the output register, the first rising edge after reset captures the reset value of `gray_wire`. The second rising edge captures the first increment, `0001`. The self-written test had encoded the original output phase, so it could check sequence and cadence while accepting the wrong startup latency. When the conversions already match their equations, trace the internal Gray value and the visible output separately through the first few edges after reset. A two-cycle cadence alone leaves the edge of the first visible increment unspecified.
