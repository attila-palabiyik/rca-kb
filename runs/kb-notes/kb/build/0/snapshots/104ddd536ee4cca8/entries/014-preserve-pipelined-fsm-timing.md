# Trace registered outputs before changing a timed FSM

In the traffic-light `TopModule`, the reference fixed two transition targets. At `cnt == 3`, red enters green and green enters yellow. Yellow already entered red. The reference preserved the idle reset state, the registered light buffers and outputs, and the counter reload logic.

The submitted rewrite updated the light and countdown together and asserted red during reset. It passed a self-written Icarus test based on the prose specification, including pedestrian requests at every green count. Grading reported 220 mismatches out of 517 samples. The reference diff establishes the intended patch. The grading report gives no individual mismatch traces.

For a timed FSM with registered outputs, check transition targets against the requested sequence first. Trace the old and new values of the state, output buffers, visible outputs, and timer on each edge before changing a threshold or removing a stage. Here, the edge that sees count 3 changes the internal state at count 2. The next edge updates the light buffer at count 1. On the following edge, the visible light changes and the counter reloads because the timer block sees the buffer high and the corresponding visible light still low. A targeted test can check this boundary and the first few edges after reset. If the prose and existing reset or output timing conflict, record the discrepancy explicitly so a test based on one interpretation does not silently settle it.

In a later traffic-light `TopModule` variant, the transition targets were already correct. The green reload incorrectly used `green && p_green`, which missed the entry edge and reloaded 60 on subsequent green edges. The reference used `!green && p_green`, matching the red and yellow reloads. This predicate is true on the edge that makes green visible, when the buffered green is high and the old visible green is still low. The reference also deleted a stale timing comment and preserved the idle reset with all three visible lamps off.

The submission fixed the green predicate and retained the transition pipeline, but it also initialized the state, buffer, and visible output directly to red and used the output register as the counter. The prose-based Icarus test passed for the normal cycle, asynchronous reset, and requests at every green count. Grading again reported 220 mismatches out of 517 samples. The reference confirms that preserving the pipeline alone was insufficient for a match when reset and startup timing changed. There were no individual mismatch traces. For a targeted reload fix, compare the three reload predicates and check that the first two visible cycles of the affected color report the initial count and the decremented count. Also check the original reset and startup trace for changes outside the patch.

In a third traffic-light `TopModule` variant, all three transition targets and reload predicates were correct. The bug was the combinational block that copied the buffered lamps to the visible lamps. Once that block settled, a predicate such as `!red && p_red` could never be true at the sampling edge during normal operation because `red` already equaled `p_red`. The reference made the visible lamps rising-edge registers with nonblocking assignments and active-low asynchronous reset, clearing all three lamps during reset. This gives each buffer a full cycle to differ from its visible lamp. The edge that captures the new lamp also samples the reload predicate and loads the new duration. The reference kept the original counter and state logic and removed the stale timing comment.

The submitted rewrite removed the pipeline and implemented immediate red with count 10 on reset, as described in the prose. Its Icarus checks passed for the requested phase lengths, asynchronous reset, and every green request count. Grading reported 220 mismatches out of 517 samples. The reference diff identifies the missing register stage and establishes that the grader expected the original reset and startup behavior. The report does not identify which individual samples differed.

When one clocked block detects a transition by comparing two copies of a signal, check that those copies actually represent distinct sampled cycles. Trace the first edges after reset as well as a normal transition. In this reference, reset leaves the lamps off with count 10. After release, the first two rising edges leave the visible lamps off at counts 9 and 8. The third rising edge makes red visible and reloads 10. A targeted test using that trace would distinguish the reference fix from the rewrite.
