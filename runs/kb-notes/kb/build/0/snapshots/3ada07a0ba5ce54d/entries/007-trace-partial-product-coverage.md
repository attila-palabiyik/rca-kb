# Trace partial products and clock stages through an adder tree

In `TopModule`, a 4-bit unsigned pipelined multiplier, each bit of `mul_b` selected one shifted partial product. The first registered adder summed `temp[0] + temp[1]`, while the second summed `temp[2] + temp[2]`, omitting the partial product for bit 3. Replacing the duplicate operand with `temp[3]` was the entire reference fix. All 43 grading samples matched.

For similar arithmetic trees, trace each generated term to the output and check that it contributes exactly once. A one-hot multiplier isolates a single term. When the input space is small, stream every input pair through the design and compare the output against the expected product at the correct cycle. An Icarus Verilog test verified all 256 pairs on consecutive cycles and confirmed that asserting reset between clock edges cleared the output and flushed pending work.

In a later 4-bit multiplier `TopModule` task, both first-stage adders already used the correct partial products. The final sum was combinational, so it followed the newly captured partial sums on the same rising edge. The submitted fix and reference both registered `mul_out <= adder_0 + adder_1` on the rising edge with an active-low asynchronous reset. All 43 grading samples matched. No alternate RTL fix was tried.

Check latency as well as arithmetic when a pipelined output is driven by a combinational block. For this two-stage multiplier, operands captured on one rising edge appear at the output on the following rising edge. The Icarus test checked all 256 products using the preceding input pair as the expected value on each edge. It also asserted reset between edges while a nonzero product was pending and checked that the output cleared immediately and that the pending product was discarded.

In another 4-bit multiplier `TopModule` task, the adder tree used all four partial products, but each term used `mul_a << (i-1)`. A term gated by `mul_b[i]` has weight `2**i`, so its shift count is `i`. In particular, `mul_b = 4'b0001` should pass `mul_a` through the pipeline. The submission and reference changed only the shift expression to `mul_a << i`. All 43 grading samples matched. Icarus also passed all 256 consecutive input pairs with the original pipeline timing.

The first midstream reset check released reset and then let a rising edge sample the old input values before driving fresh operands. The old product reappeared because the pipeline had sampled those operands again. The corrected test asserted and released reset between rising edges and drove fresh operands before the next rising edge. It verified immediate clearing, a zero on the first rising edge after release, and the fresh product on the following edge. When testing a pipeline flush, track every sampling edge after reset release and which inputs were present at each edge.
