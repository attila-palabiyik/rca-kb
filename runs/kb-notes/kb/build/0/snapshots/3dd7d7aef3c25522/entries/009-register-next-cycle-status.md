# Register a status flag specified for the next cycle

In the decimal up/down counter `TopModule`, the original combinational `zero` tracked the current `number` as soon as the count changed. It also asserted on reset release while the count was still zero. The fix registered `zero <= (number == 4'd0)` on the rising clock edge and cleared `zero` on assertion of the active-low asynchronous reset. The comparison samples the count before the edge, so the flag asserts on the edge that leaves zero. The submitted change matched all 289 grading samples, and the reference used the same timing with an explicit `if`/`else` comparison. No alternate fix was tried.

For a flag specified for the cycle after a condition, check both the edge that enters the condition and the following edge. In this counter, check `9 → 0 → 1` when counting up and `1 → 0 → 9` when counting down. Also check that the flag stays low from reset release until the first rising edge, when it samples the reset count of zero.

In the overlapping `1011` detector `TopModule`, the original combinational `flag` went high on the edge that sampled the final `1` and entered `S4`. The submission and reference both registered `flag <= (state == S4)` with an active-low asynchronous reset. Sampling the pre-edge state made `flag` go high one rising edge after the final bit. The submission matched all 153 grading samples. No alternate fix was tried.

To test this delay, drive `10110111` and check the flag just after each rising edge. The matches end on samples 4 and 7, and the one-cycle pulses appear on samples 5 and 8. The Icarus test also asserted reset while the flag was high and checked all 4,096 twelve-bit streams against the previous four sampled bits.

In a later decimal up/down counter `TopModule` task, both mode branches subtracted one on ordinary steps, while their wraparound cases were correct. The submitted fix changed the up branch to `number + 4'd1` and matched all 289 grading samples. The reference used `number + 1'd1`. The existing registered `zero` logic passed as written. For up/down logic, check an ordinary step in each direction as well as each wraparound. A wraparound-only test would miss the wrong operator here.

In another decimal up/down counter `TopModule` task, the up branch checked the pre-edge count against `10`, so the step from `9` produced `10`. The reference changed only the comparison to `9`. The submitted fix used `4'd9` and sized the wrap assignment as `4'd0`. It matched all 289 grading samples. Icarus verified both counting directions, asynchronous reset, and the existing registered `zero` timing. No alternate fix was tried. For an up counter that wraps on a comparison against its current value, compare against the last valid count and check the next two edges. Here `9 → 0 → 1` produces `zero = 0` at `0` and `zero = 1` at `1`.

In the settable hexadecimal counter `TopModule`, the internal count `num` and the zero flag were already registered, with `zero` comparing the pre-edge `num`. The reference replaced the combinational `number` output with an asynchronously reset register that also samples the pre-edge `num`. After a rising edge, both outputs therefore describe the same count, and a value loaded into `num` by `set` appears at `number` on the following rising edge. Reset clears both outputs, so the reset pair is `number = 0, zero = 0`.

The submitted rewrite removed the internal count stage, updated both outputs from the next count, and asserted `zero` during reset. Icarus passed a testbench written for that interpretation, but 248 of 273 grading samples differed. When a registered flag already reads internal state and the data output bypasses that register stage, trace both outputs before changing which state the flag samples. To distinguish the two timings here, release reset and set `set_num = B` with `set = 1` for the first rising edge. The reference gives `(number, zero) = (0, 1)` on that edge and `(B, 0)` on the next, even if `set` is deasserted for the second edge. The submitted rewrite gives `(B, 0)` and then `(C, 0)`. Check the reset pair separately.

In a later settable hexadecimal counter `TopModule` task, `number` and `zero` already sampled the same pre-edge `num`, but `zero` compared it against `4'd1`. The submitted and reference fixes changed only the comparison to `4'd0`, and all 273 grading samples matched. Icarus verified counting, wraparound, all 16 set values, the delay from load to output, and asynchronous reset. When a flag and its data output already sample the same register on the same edge, check the predicate against the value that appears at the output. For this bug, the displayed sequence `F → 0 → 1` should produce `zero = 0 → 1 → 0`.
