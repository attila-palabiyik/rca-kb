For an isolated combinational output-valid timing bug in a registered width converter, sample the existing word-boundary predicate on the output register clock with the established reset behavior, checking the predicate separately before changing its qualification.

Applies to isolated timing faults in a width converter with registered output data. A wrong boundary count is a separate predicate bug. For an isolated counter bug, see [ready-valid-counter-enable.md](ready-valid-counter-enable.md). In one 24-to-128-bit `TopModule` variant, `data_out` updated on valid input at counts 5, 10, and 15, while `valid_out` checked 12 for the middle boundary. Changing that literal from 12 to 10 matched all 261 reference samples. In another variant, `valid_out` already checked the correct counts but drove the result combinationally. Registering that result on the rising clock edge and clearing it on the same asynchronous active-low reset as `data_out` matched all 261 reference samples.

In the 1-to-6-bit serial-to-parallel `TopModule` with combinational `valid_b`, the reference registered the pre-edge comparison `cnt == 5` on the rising edge and cleared `valid_b` on active-low asynchronous reset. The reference kept the comparison independent of `valid_a` and kept `ready_a` registered with reset value 0. The submitted change also qualified `valid_b` with `valid_a` and tied `ready_a` high. It passed local Icarus tests for the rewritten handshake and differed from the reference on 16 of 151 samples. The grading report did not isolate the effects of the two extra changes.
