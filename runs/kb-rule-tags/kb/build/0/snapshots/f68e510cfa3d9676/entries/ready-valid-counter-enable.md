For an isolated ready/valid beat counter bug, check that the counter advances only on accepted transfers and reaches the terminal count used by the existing output logic, preserving the surrounding reset and output timing.

Applies to counters that track accepted transfers, including zero-based counters that wrap when a word completes. In one 1-to-6-bit serial-to-parallel `TopModule` variant, the reference fixed the counter enable by changing the hold condition from `~ready_a && ~valid_a` to `~ready_a || ~valid_a`. In a second variant, the enable was already correct, but wrapping at count 4 made the existing output checks at count 5 unreachable. The reference changed only the wrap comparison from 4 to 5, preserving the registered `ready_a` that reset low and the registered `valid_b` driven by `cnt == 5`. In both variants, tying `ready_a` high and gating `valid_b` on the sixth accepted beat passed local Icarus tests but differed from the reference on 16 of 151 samples. Neither grading report attributed individual mismatches to a particular change.
