# Output valid and word completion

Applies when a word packer or similar accumulator asserts output valid before the edge that writes the word, misses a completed word, or reasserts valid during idle cycles at a completion boundary.

If the word boundary itself moves during an input stall, compare the counter enable with the input capture enable first. The [ready/valid word counter guide](ready-valid-word-counters.md) covers a case where fixing the count was sufficient for the reference, which retained different enables for output valid and output data.

1. Find the clock-edge condition that writes the output data. Trace the counter just before that edge and identify whether it counts accepted inputs or elapsed clocks. With nonblocking assignments, a counter that has already counted five inputs still reads as five on the edge that accepts the sixth.
2. Compare the data-write and valid conditions on the same edge. Check both the input acceptance gate and each completion count. If the counts differ, drive an accepted input at each differing count and check for a missing pulse where data is written and a spurious pulse where data is held. Pause immediately before a completion beat to distinguish an acceptance-gated pulse from a count-only decode. An OR between acceptance and completion lets valid assert on both partial inputs and stalls at completion. If the interface specifically requires one pulse per newly written word, the pulse and data write need the same acceptance-and-completion condition.
3. Check how the conditions are sampled even when the predicates differ. With a combinational valid decode, an update to the counter or `valid_in` can raise valid while the output register still holds the previous word. On the completion edge, the counter can advance and drop valid just as the new word appears. Keep input valid high through completion and check both outputs before and after the rising edge. If the failure is a one-edge timing shift, test registering the existing decode before changing its predicate. Check asynchronous reset and use a stall to expose any remaining differences in the predicates.
4. Check packing independently before changing counter thresholds or slices. For `TopModule.sv`, the 24-to-128-bit packer completed words on accepted inputs 6, 11, and 16 of each 16-input group. Those words used 8, 16, and 24 high bits of the incoming beat, respectively. A bit-stream scoreboard checked bit order and carryover across those boundaries, with gaps immediately before completion and an asynchronous reset while output valid was high.

- In the `TopModule.sv` 24-to-128-bit converter with premature and idle-cycle output valid, changing OR to AND in the registered `valid_out` condition passed all 261 grading samples.
- In the `TopModule.sv` 24-to-128-bit converter with a missing pulse and a later spurious pulse, the acceptance gate was already correct. The data write used counts 5, 10, and 15, while `valid_out` used 5, 12, and 15. The 11th accepted input wrote the second word without a pulse, and the 13th raised a pulse while holding that word. A local bit-stream scoreboard confirmed the packing, so only the middle valid count changed from 12 to 10. The one-line fix matched all 261 grading samples.
- In the `TopModule.sv` 24-to-128-bit converter with combinational `valid_out`, both conditions already used `valid_in` and counts 5, 10, and 15. For example, with continuous input, valid rose after the fifth input advanced the counter to 5 and fell after the sixth input wrote the first word and advanced the counter to 6. Registering the existing decode with an active-low asynchronous reset matched all 261 grading samples. The counter and packing logic required no edits.

## Serial-to-six-bit converter with combinational output valid

In this `TopModule.sv` task, the counter already wrapped at five and held during input stalls. The shifter and output register already packed the first bit into bit 0 and the sixth into bit 5. The combinational `valid_b = (cnt == 5)` asserted after the fifth accepted bit and deasserted when the sixth bit updated `data_b`. The supplied fix kept the count-only decode and sampled it on `posedge clk`, with `negedge rst_n` clearing `valid_b` asynchronously. With continuous valid input, the corrected `valid_b` rises on the same edge that writes `data_b`.

A stall after five accepted bits distinguishes the decode from a word-completion pulse. On a stalled edge with `cnt == 5`, the supplied fix sets `valid_b` high while `data_b` holds. If the stall continues, valid stays high through it and through the edge that accepts the sixth bit. A separate reset check distinguishes the ready behaviors. The supplied fix keeps `ready_a` low during reset and raises it on the first edge out of reset, so the counter and shifter first accept input on a later edge.

The submitted rewrite also tied `ready_a` high and gated `valid_b` with acceptance of the sixth bit. Its Icarus scoreboard passed because it expected those two behaviors. Grading reported 16 mismatches out of 151 samples, without a signal-level breakdown. For similar timing failures, use continuous input to isolate the sampling edge, then use a boundary stall and valid input on the first edge out of reset to check for any unintended changes to the surrounding handshake.
