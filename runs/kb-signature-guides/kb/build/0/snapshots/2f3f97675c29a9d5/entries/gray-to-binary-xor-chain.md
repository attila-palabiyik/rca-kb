# Gray-to-binary XOR chain in a counter

Use this guide when a Gray counter starts correctly but skips codes or changes multiple bits on an advance. It also applies when a Gray-to-binary converter gives the correct upper bits and an incorrect low bit for some inputs.

1. Trace the first wrong advance through the Gray-to-binary conversion, the binary increment, and the binary-to-Gray conversion. In the 4-bit `TopModule.sv` counter, the feedback value `0011` should decode to binary `0010`. A low-bit expression using `bin_out[3]` gives `0011`, so the ordinary increment and Gray encoder produce `0110` instead of the expected `0010`. Reset and the first two advances alone leave this dependency error hidden.
2. Check the XOR chain from the most significant bit down. The top binary bit equals the top Gray bit. Every lower binary bit is its Gray bit XOR the binary bit immediately above it. Equivalently, binary bit `i` is the XOR of Gray bits from the top through bit `i`. If the converter computes those bits in order with blocking assignments in a single clocked block, changing them mechanically to nonblocking assignments makes the dependent expressions use old values. For an isolated converter, `0011` is a quick check, and a round trip through both conversions can cover all 16 inputs.
3. Trace the cadence separately before changing the clocking. In this counter, the decoder and increment registers formed a two-edge feedback path, and the output register sampled the encoded increment. With the corrected XOR chain, the output after the first six rising edges from reset is `0000, 0001, 0001, 0011, 0011, 0010`. The two-edge cadence already follows from the pipeline and its reset values. Check the holds, all 16 codes, the one-bit wrap from `1000` to `0000`, and asynchronous reset during counting.

The source task was the 4-bit Gray counter in `TopModule.sv`. The grading reference changed only the second operand of the low-bit XOR from `bin_out[3]` to `bin_out[1]`. The submitted implementation used combinational conversion and increment with an alternating clock enable. It passed the local sequence and reset simulation and matched all 421 grading samples. The reference shows the datapath correction was sufficient with the original clocking.
