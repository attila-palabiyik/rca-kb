# Ready/valid acceptance and word counters

Applies when a ready/valid receiver loses word alignment after idle cycles or reset, or fails to produce complete words even with continuous valid input.

1. Compare the input capture and counter enables using signal values just before the sampling edge. When the shift register captures on `ready_a && valid_a`, the counter must hold on `!ready_a || !valid_a`. An earlier `TopModule.sv` serial-to-6-bit converter used AND between the negated inputs and advanced the count when exactly one handshake signal was high. Its supplied correction changed that AND to OR.
2. Exercise both one-high cases. Insert an idle edge with `ready_a=1` and `valid_a=0`, then check that the count and shift register both hold. If ready is registered and cleared on reset, drive `valid_a=1` on the first edge after reset release. The pre-edge `ready_a=0` prevents acceptance even though ready rises after the edge.
3. If the enables agree, drive a full word with continuous valid input and trace the pre-edge count against the output data and valid conditions. For a count starting at zero, a six-bit word needs the sixth accepted edge to see count five. In a separate `TopModule.sv` serial-to-6-bit converter task, the counter wrapped at four, so the output conditions at five were unreachable. The supplied correction changed only the counter wrap comparison from `cnt == 4` to `cnt == 5`.
4. Trace output data and valid separately with a stall after five accepted bits. In both supplied corrections, an edge at count five with `valid_a=0` holds `data_b` and registers `valid_b=1`. When the sixth bit arrives, the output captures the word with the first bit at bit 0 and valid can stay high across that edge. Ready is registered and clears during reset. Check whether ready timing or valid timing contributes to the observed failure before editing either signal.

In the wrap-threshold task, the submitted rewrite fixed the threshold, tied ready high through reset, and gated output valid with the sixth accepted bit. Its local scoreboard expected those handshake changes and passed, while grading reported 16 mismatches out of 151 samples. The earlier acceptance-enable task reported the same mismatch count after the same handshake changes. Neither result broke down the mismatches by signal.
