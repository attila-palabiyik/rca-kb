# Debug Verilog cycle alignment

1. Trace each input to the output through its registers. For a clocked block using nonblocking assignments, the right-hand side reads values from before the edge. After those assignments take effect, a combinational check sees the updated values. When two checks describe parts of the same window or transaction, label the cycle each one observes.
2. Use the existing registered paths and the timing specification to identify the intended sample. If all checks already sample the intended window together, verify their bit slices and comparison constants against the pattern before changing the pipeline. For a shift register, trace where the new bit lands and where it moves on subsequent edges. Confirm that each retained bit advances by one position and that the checked slices hold the expected oldest and newest samples. If an operand or check bypasses a register stage, first evaluate a local fix that aligns the paths. When a register is missing from one path, match the clock and reset of the parallel stage. Drive consecutive samples for which mixing an older registered value with a newer bypassed value would change the result. Check whether evaluating the incoming data or adding a startup counter would change the output edge or post-reset behavior.
3. Simulate an isolated match and check the output after nonblocking updates on the completion edge and the following edge. Exercise reset and startup too. Derive the expected cycle and reset behavior independently of the candidate patch so the test can distinguish a wrong output edge from a wrong result.
4. When replacing a clocked output block with combinational decoding of registered state, carry over any explicit reset override required by the outputs. A state register with asynchronous reset still updates through a nonblocking assignment. At reset assertion the decoder can see the old state until that update, and at startup the state can be unknown. If the outputs must be inactive whenever reset is low, include reset directly in the combinational block. Test reset held low at startup and reset asserted between clock edges while an output is high. A check after a delay observes only settled values.
5. For a pointer that also drives a synchronous RAM address, trace feedback from the pointer through the enable and next-address logic. A combinational block that assigns the pointer from its own next value can advance before the RAM samples the address. Compare it with the other pointer's clock and reset block. Try restoring the missing register first. Drive an enable between rising edges, check that the pointer and flags hold before the edge, then confirm the RAM uses the old address and the pointer advances once.
6. When a registered `valid_out` marks a write to a registered data output, compare its predicate with the data write enable using the same pre-edge state. If there are several completion branches, compare every count in the flag predicate with the corresponding data write branch. If a valid input must complete the word, both input validity and the completion condition must hold. Test valid inputs at every completion position and between completions, plus an idle cycle at a completion position.
7. For a staging register feeding a registered output, check which branch captures the input and which holds the old value. Start with a valid sample and then drive a different value on an idle cycle before completing the transaction. A staging register can also capture on the completion edge if the output uses its pre-edge value and the next transaction overwrites it before use.
8. When a status flag must report a state condition on the following cycle, register the comparison of the current state with a nonblocking assignment and give the flag its specified reset value. Check the edge that enters the matching state and the next edge separately. If reset initializes the state to a matching value while clearing the flag, release reset between clock edges and check the flag both before and after the first active edge. A combinational decode can assert on reset release or a cycle early during normal operation.
9. When a bidirectional counter has a registered status flag, check the ordinary step and the wrap in each direction. Drive a mode change and check the count against the new direction and the flag against the pre-edge count. If the flag already samples the intended count, focus the fix on the failing count branch.
10. When a counter tracks accepted input beats, compare its advance enable with the data capture enable for all four ready and valid combinations. If capture requires `ready && valid`, the counter's hold condition is `!ready || !valid`. Check stalls at the terminal count and the first edge out of reset, when a registered ready signal can still be low before the edge. Try correcting the counter predicate alone first. Trace and test the existing reset and output timing before changing either, especially when a high-level description calls a registered ready signal always ready.

## Observed results

In the `011XXX110` shift-register detector task in `TopModule.sv`, the combinational prefix comparison saw the newly shifted window while the registered suffix comparison used the pre-edge window. The submitted fix registered comparisons of the window including the incoming bit and added a nine-sample startup guard. Its self-written Icarus test passed all 512 windows and 4,096 streaming samples under those assumptions. The grader reported 16 mismatches in 237 samples.

The supplied correct fix registered the prefix comparison on the same clock edge as the suffix comparison and used the same asynchronous active-low reset. Both comparisons therefore use the pre-edge shift-register contents. A matching window is reported one rising edge after its last bit enters the register. The reference also preserves the original zero-filled reset window and adds no startup counter.

In a separate `011XXX110` detector task in `TopModule.sv`, both comparisons were already registered and the prefix constant was `001`. Changing only that constant to `011` matched all 237 graded samples and preserved the pre-edge comparison and zero-filled reset window.

In another `011XXX110` detector task in `TopModule.sv`, the registered comparisons already checked the correct slices of the pre-edge window. The assignment `{a, a_tem[7:0]}` replaced bit 8 each cycle and held bits 7 through 0 in place. The submitted and reference fixes both changed the assignment to `{a_tem[7:0], a}`, which captures the new sample in bit 0 and advances the older samples toward bit 8. The submission matched all 237 graded samples with the existing one-edge reporting delay and zero-filled reset window.

In the non-overlapping `011100` detector task in `TopModule.sv`, the submitted fix replaced clocked outputs with combinational decoding of the sixth-bit success and failure states. It relied on the state register's reset to clear the outputs. Its Icarus test passed all 64 six-bit groups and checked reset after a delay. The grader reported one mismatch in 1,215 samples. The supplied correct fix also decodes the sixth-bit states combinationally and explicitly forces both outputs low when `rst_n` is low. The grading feedback did not identify the mismatching sample.

In the synchronous dual-port RAM FIFO task in `TopModule.sv`, the write pointer updated combinationally while the read pointer was clocked. The reference fix put the write pointer in a rising-edge block with asynchronous active-low reset and nonblocking assignments, matching the read pointer. The submitted fix also changed the flag comparisons, qualified both RAM enables with reset, and handled depth one. It matched all 327 graded samples. The reference diff identifies the write-pointer update as the required change for this task.

In the 24-bit to 128-bit width converter task in `TopModule.sv`, the data register already updated on valid inputs at pre-edge counts 5, 10, and 15. The reference fix changed the OR between the completion check and `valid_in` to AND. The submitted fix made the same change and matched all 261 graded samples.

In a separate 24-bit to 128-bit width converter task in `TopModule.sv`, `valid_out` already required `valid_in`, but its middle count was 12 while the data register wrote at count 10. The submitted and reference fixes changed only that comparison to 10, aligning all three completion cases. The submission matched all 261 graded samples.

In the 8-bit to 16-bit width converter task in `TopModule.sv`, the staging register incorrectly captured input on idle cycles and held its value on valid cycles. The reference swapped the two branches so the register captures every valid byte. The submitted fix captured only the first byte of each pair and matched all 141 graded samples. On the second valid byte, the registered output uses the pre-edge staged byte as its high byte, so capturing again on that edge is safe in this design.

In the three-input unsigned minimum task in `TopModule.sv`, the second registered comparator consumed the previous cycle's `min(a, b)` and the current `c`. Both the submitted and reference fixes registered `c` on the first comparator's rising edge with the same asynchronous active-low reset. The two operands then reached the second comparator from the same sample, and `d` reported that sample's minimum on the next rising edge. The submitted fix matched all 421 graded samples.

In the decimal up/down counter task in `TopModule.sv`, the original combinational `zero` flag decoded the updated `number`. Both fixes registered the pre-edge comparison `number == 4'd0` and cleared the flag with asynchronous active-low reset. During counting, `zero` asserted on the rising edge after the count reached zero. After reset release, the first active rising edge sampled the reset count of zero and asserted the flag. The reference used a separate clocked block for `zero`, and the submitted fix updated both outputs in one clocked block. The submission matched all 289 graded samples.

In a separate decimal up/down counter task in `TopModule.sv`, `zero` already sampled the pre-edge count and both wrap branches were correct. The ordinary up-count branch subtracted one. The submitted fix changed it to `number + 4'd1`, and the reference used `number + 1'd1`. This single change matched all 289 graded samples.

In the six-bit serial-to-parallel converter task in `TopModule.sv`, the shift register captured on `ready_a && valid_a`, but the counter held only when both signals were low. The supplied reference changed only the counter's hold condition from `~ready_a && ~valid_a` to `~ready_a || ~valid_a`. It retained registered `ready_a`, which clears during reset and rises on the first active edge, and registered `valid_b`, which samples `cnt == 5` even during a stall at that count. The submitted fix also tied `ready_a` high and qualified `valid_b` with `valid_a`. Its Icarus checks passed under those assumptions, but the grader reported 16 mismatches in 151 samples. The feedback gave the reference diff and the total mismatch count.
