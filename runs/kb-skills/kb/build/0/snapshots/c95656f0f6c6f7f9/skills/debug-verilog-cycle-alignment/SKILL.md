description: Diagnose Verilog or SystemVerilog timing bugs at clock and reset boundaries, including combinational feedback in state updates and misaligned output logic.

# Debug Verilog cycle alignment

1. Trace each input to the output through its registers. For a clocked block using nonblocking assignments, the right-hand side reads values from before the edge. After those assignments take effect, a combinational check sees the updated values. When two checks describe parts of the same window or transaction, label the cycle each one observes.
2. Use the existing registered paths and the timing specification to identify the intended sample. If all checks already sample the intended window together, verify their bit slices and comparison constants against the pattern before changing the pipeline. For a shift register, trace where the new bit lands and where it moves on subsequent edges. Confirm that each retained bit advances by one position and that the checked slices hold the expected oldest and newest samples. If an operand or check bypasses a register stage, first evaluate a local fix that aligns the paths. When a register is missing from one path, match the clock and reset of the parallel stage. Drive consecutive samples for which mixing an older registered value with a newer bypassed value would change the result. Check whether evaluating the incoming data or adding a startup counter would change the output edge or post-reset behavior.
3. Simulate an isolated match and check the output after nonblocking updates on the completion edge and the following edge. Exercise reset and startup too. Derive the expected cycle and reset behavior independently of the candidate patch so the test can distinguish a wrong output edge from a wrong result.
4. When replacing a clocked output block with combinational decoding of registered state, carry over any explicit reset override required by the outputs. A state register with asynchronous reset still updates through a nonblocking assignment. At reset assertion the decoder can see the old state until that update, and at startup the state can be unknown. If the outputs must be inactive whenever reset is low, include reset directly in the combinational block. Test reset held low at startup and reset asserted between clock edges while an output is high. A check after a delay observes only settled values.
5. For a pointer that also drives a synchronous RAM address, trace feedback from the pointer through the enable and next-address logic. A combinational block that assigns the pointer from its own next value can advance before the RAM samples the address. Compare it with the other pointer's clock and reset block. Try restoring the missing register first. Drive an enable between rising edges, check that the pointer and flags hold before the edge, then confirm the RAM uses the old address and the pointer advances once.
6. When `valid_out` marks a write to a registered data output, check which edge updates each signal before comparing their predicates. If the flag decodes the live counter or input combinationally, it can assert while the data output still holds the previous word. Register the write predicate using the data register's clock edge and reset so both use the same pre-edge state. If there are several completion branches, compare every count in the flag predicate with the corresponding data write branch. If a valid input must complete the word, both input validity and the completion condition must hold. Check the outputs before and after the completion edge, and insert an idle cycle at a completion count.
7. For a staging register feeding a registered output, check both when it captures and which enable selects capture. A combinational self-hold can infer a latch that follows the live input while enabled. If the output needs an earlier clocked sample, put the staging update on the output's clock edge with nonblocking assignments and the matching reset. Drive distinct consecutive valid samples and check the completed word after the edge. Repeat with a different value on an idle cycle between the samples to check the hold behavior. A staging register can also capture on the completion edge if the output uses its pre-edge value and the next transaction overwrites it before use.
8. When a status flag must report a state condition on the following cycle, register the comparison of the current state with a nonblocking assignment and give the flag its specified reset value. Check the edge that enters the matching state and the next edge separately. If reset initializes the state to a matching value while clearing the flag, release reset between clock edges and check the flag both before and after the first active edge. A combinational decode can assert on reset release or a cycle early during normal operation.
9. When a bidirectional counter has a registered status flag, check the ordinary step and the wrap in each direction. For a counter with N values starting at zero, the up branch wraps at the pre-edge count N−1 and the down branch wraps at zero. Check the edge after each terminal count to catch a comparison that lets the counter enter an out-of-range value. Drive a mode change and check the count against the new direction and the flag against the pre-edge count. If the flag already samples the intended count, focus the fix on the failing count branch.
10. When a counter tracks accepted input beats, compare its advance enable with the data capture enable for all four ready and valid combinations. If capture requires `ready && valid`, the counter's hold condition is `!ready || !valid`. Check stalls at the terminal count and the first edge out of reset, when a registered ready signal can still be low before the edge. Try correcting the counter predicate alone first. Trace and test the existing reset and output timing before changing either, especially when a high-level description calls a registered ready signal always ready.
11. For a FIFO that checks capacity before each clock edge, trace each port's request and blocking flag into the shared enable for its RAM operation and pointer advance. An asserted `full` blocks writes, and an asserted `empty` blocks reads. Check the first write after reset and an attempted write at full. If the enable uses the wrong flag polarity, correct that predicate first. For circular pointers with an extra wrap bit, compare the two wrap conditions on each pointer. An accepted operation at address `DEPTH-1` must zero the RAM address and toggle the wrap bit on the same edge. Fill and drain at least twice, checking data order and both flags. The last read of the first drain should assert `empty`, and a further read request should leave the registered RAM output unchanged.

12. When a Gray-code counter decodes a feedback value before incrementing, trace both conversions and the feedback timing before changing the registers. For reflected Gray code, encode with `binary ^ (binary >> 1)`. Decode each bit by XORing its Gray bit with all higher Gray bits, or by XORing it with the binary bit immediately above it. Check the encoder shift and the decoder dependencies separately. Trace the internal feedback wire and the visible output separately on the first two rising edges after reset. If the feedback has the required cadence and the visible output appears a clock early, try registering the output from the feedback wire while preserving the feedback path. Check for blocking assignments in clocked stages whose results another block samples on the same edge. A registered decoder can use XOR reductions of the Gray input slices with nonblocking assignments so a parallel increment stage samples the prior decoded value. Verify the first update after reset, all code values, and wraparound.

13. For a fractional divider, derive the period schedule from the counter terminal counts and the mode switch points. Then trace the high and low pulse lengths from each mode's output comparator, including the inclusive count at `<=` and the pre-edge count sampled by a registered output. If the requested average frequency and mode schedule already agree with the counters, inspect the output branches before changing the counters. Compare parallel branches for an isolated shift or threshold error, and use any established pulse-width requirement to choose the correction. A frequency-only specification cannot distinguish pulse widths that produce the same rising-edge cadence. Check both edges against an expected waveform across mode switches, schedule wraparound, and reset.

14. When an FSM announces a timed transition through registered outputs, trace the expiry comparison, internal state change, visible output change, and timer reload as separate events. Compare the reload predicates for each phase. If an intermediate signal is copied into a visible register on the same edge as the reload check, `!visible && intermediate` detects the upcoming rise. `visible && intermediate` is true throughout their shared high interval and can reload the timer every cycle. Test the entry edge, the next two countdown samples, and reset release to detect changes to the pipeline timing. In an earlier traffic light variant, the reference retained distinct events at pre-edge counts of 3, 2, 1, and 0 for the state change, intermediate lamp update, visible lamp update, and timer reload. Derive those offsets from the current code.

15. For a serial-to-parallel converter that starts at count zero, trace the pre-edge count on each accepted bit. Bit N arrives at count N−1. Compare the wrap branch with the registered output data's completion count. If the counter wraps earlier, first correct the wrap and verify that the completion state is reachable. In a bug-fix task, check reset and terminal-count stalls against the existing interface timing before changing ready or valid behavior. A test that hard-codes a new handshake interpretation can pass while missing an interface regression.

16. When a pipelined reduction has correct intermediate sums and the result appears one edge early, inspect the final sum for a missing output register. A combinational sum sees the intermediate registers after they update on the capture edge. A clocked final sum reads their pre-edge values and reports the product on the next edge. If the required latency calls for that second stage, register the final sum with the specified reset. Drive consecutive operands with distinct products and check the output on both edges. Assert reset between edges with a nonzero visible product and a pending product, then verify that the first edge after reset release still reports zero.

17. When a registered flag describes an exposed value that currently bypasses an output register, check whether the flag already samples the intended state. If the interface calls for both outputs to update on the clock edge, try registering the exposed value from the same pre-edge state and matching the flag's reset sensitivity. Preserve explicit reset values when the prose leaves the flag's reset behavior ambiguous. Check both the edge that changes the internal state and the following edge. A load to zero from a nonzero state, followed by an increment, distinguishes an output stage from a next-state implementation. Check reset assertion and the first active edge separately.

## Observed results

In the overlapping `1011` detector in `TopModule.sv`, the combinational `flag` decode asserted as soon as the state entered `S4`. The submitted and reference fixes clocked the existing `state == S4` comparison and gave `flag` the same asynchronous active-low reset as the state register. All 153 graded samples matched. Icarus Verilog verified all 4,096 twelve-bit streams and confirmed that `10110111` completed matches at samples 4 and 7 and pulsed `flag` at samples 5 and 8.

In the pedestrian-request traffic light task in `TopModule.sv`, the green timer reload checked `green && p_green`, which reloaded the timer while both green signals were high. The supplied reference changed that predicate to `!green && p_green`, matching the rising-edge checks for red and yellow, and removed the trailing timing comment. It retained the existing reset and registered output stages. The submitted rewrite made reset immediately show red and removed the output stages. It passed local checks based on the prose specification and mismatched 220 of 517 graded samples.

In the 8.7× fractional divider task in `TopModule.sv`, the original counters already scheduled three 8-cycle periods and seven 9-cycle periods per 87 input cycles. The provided constants and counter logic established that schedule despite contradictory cycle counts in the prose. The submission changed the odd-period output comparator from `div_o >> 2` to `div_o >> 1` and widened the counters. Its Icarus test passed with an assumed six high samples in each mode. The grader reported 460 mismatches in 2,021 samples.

The supplied correct fix changed only the even-period comparator from `div_e >> 1` to `div_e >> 2` and added parameter comments. Both output branches used `clk_cnt <= ((period >> 2) + 1)`. For the default periods, the registered output is high on counts 0 through 3 in either mode, so each pulse has four high samples. The correct fix retains the original counter widths and mode-switch timing. The successful frequency check in the submitted test could not distinguish the two waveforms.

In a follow-up 8.7× divider variant, the even-period comparator used `div_e >> 3`, which gave a three-cycle high pulse. Changing only that shift to `div_e >> 2` matched all 2,021 graded samples. The Icarus test checked three periods with four high and four low samples each, then seven with four high and five low samples each, across repeated schedules and after asynchronous reset.

In the `011XXX110` shift-register detector task in `TopModule.sv`, the combinational prefix comparison saw the newly shifted window while the registered suffix comparison used the pre-edge window. The submitted fix registered comparisons of the window including the incoming bit and added a nine-sample startup guard. Its self-written Icarus test passed all 512 windows and 4,096 streaming samples under those assumptions. The grader reported 16 mismatches in 237 samples.

The supplied correct fix registered the prefix comparison on the same clock edge as the suffix comparison and used the same asynchronous active-low reset. Both comparisons therefore use the pre-edge shift-register contents. A matching window is reported one rising edge after its last bit enters the register. The reference also preserves the original zero-filled reset window and adds no startup counter.

In a separate `011XXX110` detector task in `TopModule.sv`, both comparisons were already registered and the prefix constant was `001`. Changing only that constant to `011` matched all 237 graded samples and preserved the pre-edge comparison and zero-filled reset window.

In another `011XXX110` detector task in `TopModule.sv`, the registered comparisons already checked the correct slices of the pre-edge window. The assignment `{a, a_tem[7:0]}` replaced bit 8 each cycle and held bits 7 through 0 in place. The submitted and reference fixes both changed the assignment to `{a_tem[7:0], a}`, which captures the new sample in bit 0 and advances the older samples toward bit 8. The submission matched all 237 graded samples with the existing one-edge reporting delay and zero-filled reset window.

In the non-overlapping `011100` detector task in `TopModule.sv`, the submitted fix replaced clocked outputs with combinational decoding of the sixth-bit success and failure states. It relied on the state register's reset to clear the outputs. Its Icarus test passed all 64 six-bit groups and checked reset after a delay. The grader reported one mismatch in 1,215 samples. The supplied correct fix also decodes the sixth-bit states combinationally and explicitly forces both outputs low when `rst_n` is low. The grading feedback did not identify the mismatching sample.

In the synchronous dual-port RAM FIFO task in `TopModule.sv`, the write pointer updated combinationally while the read pointer was clocked. The reference fix put the write pointer in a rising-edge block with asynchronous active-low reset and nonblocking assignments, matching the read pointer. The submitted fix also changed the flag comparisons, qualified both RAM enables with reset, and handled depth one. It matched all 327 graded samples. The reference diff identifies the write-pointer update as the required change for this task.

In a separate synchronous dual-port RAM FIFO task in `TopModule.sv`, both pointers were already clocked. The write enable was `winc & wfull`, so a write request at empty was blocked. The reference corrected the enable to `winc & (!wfull)`. The submission corrected that polarity and also qualified the enables with reset, simplified the flag comparisons, and handled depth one. It matched all 327 graded samples. The reference diff shows that the polarity change was sufficient.

In another synchronous dual-port RAM FIFO task in `TopModule.sv`, the read address returned to zero at `DEPTH-1`, while the read wrap bit checked `DEPTH`. The reference changed the wrap-bit check to `DEPTH-1`. The submission shared each pointer's wrap condition between its low address and wrap bit, used direct pointer comparisons for the flags, and handled depth one. It matched all 327 graded samples. The reference diff shows that the read wrap-bit predicate was the only required logic change.

In the 24-bit to 128-bit width converter task in `TopModule.sv`, the data register already updated on valid inputs at pre-edge counts 5, 10, and 15. The reference fix changed the OR between the completion check and `valid_in` to AND. The submitted fix made the same change and matched all 261 graded samples.

In a separate 24-bit to 128-bit width converter task in `TopModule.sv`, `valid_out` already required `valid_in`, but its middle count was 12 while the data register wrote at count 10. The submitted and reference fixes changed only that comparison to 10, aligning all three completion cases. The submission matched all 261 graded samples.

In a third 24-bit to 128-bit width converter task in `TopModule.sv`, the combinational `valid_out` predicate already matched the data register's write enable at counts 5, 10, and 15. It asserted before the data write and could deassert as the counter advanced on that edge. Both fixes registered the existing predicate on the rising edge with asynchronous active-low reset, so `valid_out` and `data_out` updated together. The submission matched all 261 graded samples.

In one 8-bit to 16-bit width converter task in `TopModule.sv`, the clocked staging register incorrectly captured input on idle cycles and held its value on valid cycles. The reference swapped the two branches so the register captures every valid byte. The submitted fix captured only the first byte of each pair and matched all 141 graded samples.

In a separate variant of the same converter, the staging enable was already `valid_in`, but the combinational self-hold let the second byte overwrite the first before the output sampled it. The reference moved the staging update to the rising clock edge with asynchronous active-low reset and nonblocking assignments, retaining capture on every valid byte. The submission used the same clock and reset and captured only the first byte of each pair. It matched all 141 graded samples. On the completion edge, the output reads the pre-edge staged byte for its high byte, and the first byte of the next pair replaces the staged value before the next output.

In the three-input unsigned minimum task in `TopModule.sv`, the second registered comparator consumed the previous cycle's `min(a, b)` and the current `c`. Both the submitted and reference fixes registered `c` on the first comparator's rising edge with the same asynchronous active-low reset. The two operands then reached the second comparator from the same sample, and `d` reported that sample's minimum on the next rising edge. The submitted fix matched all 421 graded samples.

In the decimal up/down counter task in `TopModule.sv`, the original combinational `zero` flag decoded the updated `number`. Both fixes registered the pre-edge comparison `number == 4'd0` and cleared the flag with asynchronous active-low reset. During counting, `zero` asserted on the rising edge after the count reached zero. After reset release, the first active rising edge sampled the reset count of zero and asserted the flag. The reference used a separate clocked block for `zero`, and the submitted fix updated both outputs in one clocked block. The submission matched all 289 graded samples.

In a separate decimal up/down counter task in `TopModule.sv`, `zero` already sampled the pre-edge count and both wrap branches were correct. The ordinary up-count branch subtracted one. The submitted fix changed it to `number + 4'd1`, and the reference used `number + 1'd1`. This single change matched all 289 graded samples.

In another decimal up/down counter task in `TopModule.sv`, the up branch compared the pre-edge count to 10, allowing the count to reach 10 before wrapping. The submission and reference changed only that comparison to 9, so the edge after 9 produced 0. The submission used `4'd9` and matched all 289 graded samples. Icarus Verilog also verified both wrap directions, mode changes, the registered `zero` delay, and asynchronous reset.

In the hexadecimal settable counter task in `TopModule.sv`, `zero` already sampled the pre-edge `num`, while combinational `number` exposed the newly updated `num`. The supplied correct fix registered `number <= num` on the rising edge with asynchronous active-low reset. After reset release, both outputs describe the pre-edge `num`, so a set value becomes visible one rising edge after capture. Reset clears both outputs. The first active edge reports `number = 0` and `zero = 1` from the reset state of `num`. The submission exposed the newly updated count and asserted `zero` during reset. Its Icarus checks passed under those assumptions, and the grader reported 248 mismatches in 273 samples.

In the six-bit serial-to-parallel converter task in `TopModule.sv`, the shift register captured on `ready_a && valid_a`, but the counter held only when both signals were low. The supplied reference changed only the counter's hold condition from `~ready_a && ~valid_a` to `~ready_a || ~valid_a`. It retained registered `ready_a`, which clears during reset and rises on the first active edge, and registered `valid_b`, which samples `cnt == 5` even during a stall at that count. The submitted fix also tied `ready_a` high and qualified `valid_b` with `valid_a`. Its Icarus checks passed under those assumptions, but the grader reported 16 mismatches in 151 samples. The feedback gave the reference diff and the total mismatch count.

In a follow-up six-bit serial-to-parallel converter task in `TopModule.sv`, the counter already held when either ready or valid was low. It wrapped at count 4, so the output logic at count 5 was unreachable. The supplied correct fix changed only the wrap comparison from 4 to 5. The submission also tied `ready_a` high and suppressed `valid_b` during stalls at count 5. Its Icarus tests passed all 64 output values, back-to-back words, stalls before the sixth bit, and reset under the rewritten handshake. The grader reported 16 mismatches in 151 samples. The reference retained the original registered `ready_a` and the count-only `valid_b` predicate. The grading feedback did not identify the individual mismatching samples.

In the four-bit Gray-code counter task in `TopModule.sv`, the least significant binary bit used `gray_wire[0] ^ bin_out[3]`. The reference changed only that expression to `gray_wire[0] ^ bin_out[1]`, preserving the registered feedback. The submission also replaced the registered conversion path with combinational conversion and used a toggling enable to advance on every second rising edge after reset. It matched all 421 graded samples.

In a separate four-bit Gray-code counter task in `TopModule.sv`, the encoder used `bin_add_wire ^ (bin_add_wire >> 2)`. The reference changed only the shift amount to one. The submission also used nonblocking assignments and XOR reductions in the registered decoder while retaining the existing stages. It matched all 421 graded samples. Icarus Verilog verified the first advance on the second rising edge after reset, all 16 values, wraparound, and asynchronous reset and restart.

In another four-bit Gray-code counter task in `TopModule.sv`, both conversion formulas were correct and `gray_out` exposed the feedback wire combinationally. The reference registered `gray_out` on the rising clock edge with an asynchronous active-low reset. The decoder still read `gray_wire` directly, and the reference retained the existing blocking assignments in the decoder. The submission used combinational decoding and encoding with a toggling enable to update `gray_out` on every second rising edge after reset. All 421 graded samples matched the reference. Icarus Verilog also verified the submission's first advance on the second rising edge, all 16 values, one-bit transitions through wraparound, and asynchronous reset and restart.

In the four-bit unsigned pipelined multiplier task in `TopModule.sv`, both partial-product pair sums were already correct and registered. The final sum `adder_0 + adder_1` drove `mul_out` combinationally. Both fixes registered that sum with nonblocking assignments on the rising edge and cleared `mul_out` with asynchronous active-low reset. Operands captured on one rising edge produced their result on the following rising edge, with one result per cycle after startup. The submission matched all 43 graded samples. A local Icarus simulation passed all 256 operand pairs streamed on consecutive clocks and checked reset between edges and restart.
