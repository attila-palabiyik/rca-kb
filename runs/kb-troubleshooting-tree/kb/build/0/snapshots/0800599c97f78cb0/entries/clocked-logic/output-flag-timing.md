# Check which cycle an output flag reports

**Check** which value each output samples on the edge where the predicate becomes true and on the edge where it becomes false. Trace both the flag and the associated data output through their register stages. A combinational flag follows the updated value it reads. With nonblocking assignments, two outputs that read the same source register on the same edge both sample its pre-edge value.

- **The flag should report the predicate on the following cycle.** Register the comparison against the current value using the same clock edge as the source register. If reset explicitly clears the flag, give reset priority over the comparison. Check flag timing across both reset assertion and release when the source register's reset value satisfies the predicate.
- **The flag and data output already sample the same register on the same edge.** Check the comparison against the value being published. If the comparison alone is wrong, correct its predicate and preserve the existing register stages and reset assignments.
- **The flag should reflect the updated value of a directly exposed register.** Check whether its comparison uses the value entering that register. A comparison against its pre-edge value will report the previous count.

**Observed in `TopModule.sv`**, a decimal up/down counter. The original combinational `zero` followed the current `number` and asserted as soon as reset was released while `number` was 0. The reference fix registered `number == 0` and asynchronously cleared `zero`. Thus `zero` stayed low when the count entered 0 from a nonzero value and went high at the next rising edge, when the count left 0. Reset release also left `zero` low until the first rising edge, which sampled the reset count of 0. The submitted implementation placed both assignments in one clocked block and matched all 289 graded samples.

**Observed in `TopModule.sv`**, a hexadecimal settable counter with an incorrect zero comparison. The reference changed only `num == 4'd1` to `num == 4'd0`. Both `number` and `zero` sample the old `num` on the same edge, so the comparison describes the count published by that edge. A set load or wrap reaches the outputs one rising edge after it updates `num`. Asynchronous reset clears both outputs, and the first rising edge after release publishes the reset count of zero with `zero` asserted. The description of same-edge updates and zero detection was misleading when read as a requirement to remove the existing stage and assert `zero` during reset. The submission made both changes and mismatched 248 of 273 graded samples.
