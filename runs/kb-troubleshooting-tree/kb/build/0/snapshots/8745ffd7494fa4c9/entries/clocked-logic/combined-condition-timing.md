# Check the sample cycle of each combined condition

**Check** which version of the data each condition uses immediately after a rising edge. For a shift register updated with a nonblocking assignment, a clocked condition that reads the register uses the pre-edge window. A combinational condition that reads the same register uses the post-edge window once the updates settle.

- **The conditions use different windows for a single detection.** Check the output timing established by the existing registered path. If that path uses the intended window, align the other condition to it and preserve the shift register reset value. Test a window that matches, followed by a bit that makes the next window fail. Check the output on both edges to distinguish reporting the match as the final bit enters from reporting it one edge later.
- **The conditions use the same window.** Compare that window's cycle with the required output cycle. If the cycle agrees, [check the pattern fields against the shift direction](pattern-fields.md).

**Observed in `TopModule.sv`**, a detector for `011XXX110`. Immediately after an edge, the combinational prefix check used the shifted window and the registered suffix check used the previous window. The graded fix registered the prefix check alongside the suffix check. Both checks then used the pre-edge window, so `match` reported a full pattern one edge after its final bit entered the shift register. The graded fix preserved the all-zero shift register reset. An attempted fix checked the post-edge window and changed the reset fill to all ones. Its local tests encoded immediate detection, and it disagreed with 16 of 237 reference samples. The grading established the expected clock cycle and reset implementation, without identifying which mismatches came from each change.
